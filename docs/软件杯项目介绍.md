# 软件杯项目介绍：EduMind 多智能体个性化学习平台

这份文档给刚接手项目的同学快速了解用。先看本文件，再按需要阅读 `README.md`、`PRODUCT.md` 和 `docs/A3_COMPETITION_UPGRADE.md`。

## 1. 项目一句话

EduMind 是一个面向软件杯 A3 赛题的个性化学习系统，赛题方向是“基于大模型的个性化资源生成与学习多智能体系统”。

它的核心思想是：系统先理解学生画像，再由多个智能体协作完成资源生成、路径规划、智能辅导、效果评估和反馈更新，形成一个可追溯的学习闭环。

## 2. 这个项目解决什么问题

传统学习平台通常只是展示课程、资料和题目，学生仍然需要自己判断“我该学什么、怎么补弱、下一步做什么”。

EduMind 想解决的是个性化学习中的三个问题：

1. 如何根据学生情况生成学习画像。
2. 如何根据画像生成适合这个学生的学习资源和路径。
3. 如何在学习后根据效果评估反向更新画像和后续路径。

所以项目重点不是做一个普通课程平台，而是证明“画像驱动资源、评估驱动反馈、多智能体协作闭环”。

## 3. 软件杯赛题对应关系

项目与 A3 赛题的对应点主要有这些：

| 赛题要求 | 项目中的体现 |
|---|---|
| 基于大模型 | `server/llm/provider.js` 统一接入大模型，支持无 Key 时本地 fallback |
| 个性化资源生成 | ResourceAgent 根据画像和薄弱点生成讲解、例题、练习、推荐理由 |
| 学习多智能体系统 | 6 个 Agent 加 Orchestrator 完成协作 |
| 学习画像 | ProfileAgent 根据问卷和学习数据生成画像、评分、薄弱点 |
| 学习路径规划 | PathAgent 根据画像和评估结果规划或重规划路径 |
| 智能辅导 | TutorAgent 根据画像调整讲解风格和回答深度 |
| 效果评估 | EvaluationAgent 输出掌握度变化和画像更新建议 |
| 证据链可追溯 | Evidence 页面和 trace 接口展示每次 Agent 协作过程 |

## 4. 核心智能体

项目后端在 `server/agents` 下实现了 6 个主要智能体：

| 智能体 | 作用 |
|---|---|
| ProfileAgent | 生成学习画像，识别薄弱点和学习偏好 |
| ResourceAgent | 生成个性化学习资源包 |
| PathAgent | 规划学习路径，并根据评估结果重规划 |
| TutorAgent | 做个性化答疑和辅导 |
| EvaluationAgent | 评估学习效果，给出掌握度变化 |
| ReflectionAgent | 生成反思反馈、风险提示和下一步建议 |

`orchestrator.js` 负责把这些 Agent 串起来，形成“画像分析 -> 资源生成 -> 路径规划 -> 辅导 -> 评估 -> 反馈”的闭环。

## 5. 前端主要页面

项目是 Vue 3 + Vite + TypeScript 前端，主要页面在 `src/views`。

| 页面 | 路由 | 作用 |
|---|---|---|
| 首页 | `/` | 展示项目主入口和学习闭环概览 |
| 对话页 | `/dialogue`、`/chat` | 用对话方式进入学习和问答 |
| 学习画像 | `/profile` | 填写问卷，生成画像和薄弱点 |
| 学习资源 | `/resources` | 查看个性化推荐资源 |
| 学习路径 | `/learning-path` | 查看阶段路径和路径调整 |
| 效果评估 | `/evaluation` | 查看掌握度、薄弱点和画像更新 |
| 证据链 | `/evidence` | 查看 Agent trace 和协作证据 |
| 知识宇宙 | `/universe` | 以可视化方式浏览知识结构 |
| 训练流 | `/trainflow` | 展示训练/学习流程体验 |

演示时重点看画像、资源、路径、评估、证据链这几块，因为它们最能对应软件杯赛题。

## 6. 推荐演示流程

可以按这个顺序给评委或新同学讲：

1. 首页：先说明这是一个“个性化学习多智能体闭环”系统。
2. 画像页：填写问卷，触发 ProfileAgent 生成学生画像。
3. 资源页：展示系统为什么推荐某个资源，强调推荐证据链。
4. 路径页：展示学习路径如何根据画像和评估结果调整。
5. 评估页：展示掌握度变化、薄弱点、画像更新记录。
6. 证据链页：展示每次 Agent 调用的 trace，说明系统可解释、可追溯。
7. 后端接口：如果需要技术展示，可以调用 `/api/agents/run` 演示一键完整闭环。

一句讲解主线可以这样说：

> 学生完成画像后，系统不是简单推荐资料，而是让多个智能体基于画像协作生成资源、规划路径、提供辅导，再根据学习效果更新画像和下一轮计划。

## 7. 项目结构速览

| 目录或文件 | 说明 |
|---|---|
| `src/views` | 前端页面 |
| `src/components` | 页面组件和可视化组件 |
| `src/lib/api.ts` | 前端请求后端 API 的封装 |
| `src/types/api.ts` | 前后端交互类型定义 |
| `server/index.js` | 本地 Node API 服务入口 |
| `server/agents` | 多智能体实现 |
| `server/llm/provider.js` | 大模型接入层 |
| `server/evidence` | 证据链记录与报告 |
| `server/content` | 本地 JSON 数据源 |
| `docs` | 项目说明、竞赛升级、证据链材料 |

## 8. 本地运行方式

先安装依赖：

```bash
npm install
```

启动后端 API：

```bash
npm run server
```

再启动前端：

```bash
npm run dev
```

常用校验：

```bash
npm run build
```

后端默认端口是 `8788`，前端开发服务由 Vite 启动，并通过代理访问 `/api`。

## 9. 重要接口

| 接口 | 作用 |
|---|---|
| `GET /api/health` | 检查后端是否运行 |
| `POST /api/profile/analyze` | 画像分析 |
| `POST /api/resources/generate` | 个性化资源生成 |
| `POST /api/agents/tutor` | 智能辅导 |
| `POST /api/agents/evaluate` | 综合评估 |
| `POST /api/agents/path-replan` | 路径重规划 |
| `POST /api/agents/run` | 一键跑完整多智能体闭环 |
| `GET /api/evidence/traces` | 获取证据链 trace |
| `GET /api/evidence/summary` | 获取证据链统计 |

## 11. 学妹接手建议

第一天建议先做三件事：

1. 跑起来项目，熟悉首页、画像页、资源页、路径页、评估页、证据链页。
2. 读 `server/agents`，理解 6 个 Agent 各自输入输出是什么。
3. 读 `docs/A3_COMPETITION_UPGRADE.md`，把项目功能和软件杯 A3 赛题对应起来。

后续如果要继续完善，可以优先做：

1. 把真实大模型 Key 接入并调优 Agent 输出质量。
2. 增强证据链页面的筛选、对比和导出能力。
3. 增加“一键完整闭环”的前端按钮，方便演示。
4. 补充异常状态、空状态、重试状态，提升比赛演示稳定性。
5. 准备一份演示脚本，把每个页面和赛题要求对应起来讲。

## 12. 简短汇报版本

EduMind 是一个面向软件杯 A3 赛题的个性化学习多智能体系统。系统通过 ProfileAgent 构建学生画像，再由 ResourceAgent、PathAgent、TutorAgent、EvaluationAgent、ReflectionAgent 协作完成资源生成、路径规划、智能辅导、效果评估和反馈更新。项目的核心亮点是画像驱动、评估反馈、多智能体协作和证据链可追溯，能够完整展示“基于大模型的个性化资源生成与学习闭环”。
